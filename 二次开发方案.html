1. 目标与范围

以 wyyhm6 为底，补齐课程硬性页面和产品闭环：

  • 4 个 Tab：首页 / 搜索 / 收藏 / 我的；
  • 欢迎页、固定 demo 登录、登录态持久化；
  • 收藏、最近播放、个人中心、设置；
  • 深色沉浸播放页；

  • 网络 API + 本地示例音源兜底；

不做： 真实账号系统、后台数据库、评论/社交/直播/会员、播放器底层重写、全局暗色主题。

  • 底部导航 64vp，悬浮在安全区上方；mini player 在其上方，不遮挡列表最后一项（底部留白 110–120vp）。

3.3 页面级规格

欢迎页： 暖白背景 + 淡珊瑚光晕；中央 96vp 品牌标记；“清听”36vp，“听见每一天”14vp；1.5 秒自动前进，提供“立即进入”；无 Tab/返回。

登录页： 上半部珊瑚渐变装饰区，下半部白色面板；账号/密码输入框 52vp，圆角 16vp；登录按钮 52vp；错误提示在输入框下方；页面直接显示“演示账号 demo / 123456”；协议勾选未勾选时不提交；键盘弹出可滚动。

首页： 问候 + 标题 + 搜索胶囊；16:9 精选主卡（封面 + 深色渐变遮罩 + 白字 + 珊瑚播放按钮）；“为你推荐 / 最近播放 / 精选歌单”三段；横向卡片 150vp；底部留白 120vp。网络失败时增加“当前展示本地精选”提示。

搜索： 胶囊输入框 + 搜索按钮；历史 chips；结果行 64vp，封面 48vp；当前播放歌曲用珊瑚色；加载更多失败保留已加载内容；空态/断网态分开。

收藏： 顶部“收藏”；“收藏 / 最近播放”两个 segment；列表使用统一歌曲行；空态给“去搜索一首喜欢的歌”；只提供播放和清空历史，不做每行更多菜单。

我的： 个人卡（64vp 头像、昵称、已登录/本地演示账号）；收藏数、最近播放数；一个“设置”入口 + 一个“退出登录”；不在个人卡里重复退出按钮；背景/主题设置收进设置页。

播放页（固定深色）： 见 4.6。

歌单详情： 封面 160vp + 歌单名 + 歌曲数；全部播放/随机播放；歌曲列表；底部留白 120vp。

服务卡片： 见 4.4。

3.4 状态与无障碍

  • 加载：列表底部进度，不整页遮罩。
  • 空态：图标 + 说明 + 可执行动作（重试/去搜索）。
  • 错误：区分“无结果”“网络失败”“无播放地址”。
  • 按压：0.98 缩放或背景变化；请求中主按钮禁用。
  • 图标按钮加 accessibilityText；可点目标 ≥48vp；正文对比 ≥4.5:1。

4. 技术设计

4.1 Ability 与音频所有权

EntryAbility（欢迎/登录）
  WelcomePage → LoginPage → 校验 demo/123456 → startAbility(MainAbility) → terminateSelf
                                   │
                                   ▼
MainAbility（主界面/播放，singleton）
  Index（4 Tab）
    ├─ 首页 / 搜索 ── ApiService
    ├─ 收藏 / 我的 ── StorageService
    └─ PlayPage ── PlayerService ── AVPlayer
  WidgetService（更新卡片）
  AudioSessionService（通知/后台播控）

FormExtensionAbility
  MusicFormAbility ── 动态 2×2 卡片

EntryAbility

  • 只加载 WelcomePage/LoginPage，不初始化、也不销毁音频服务。
  • 欢迎页 1.5 秒后检查 Preferences：已登录 → 启动 MainAbility；未登录 → 登录页。
  • 登录成功：保存 isLoggedIn=true、nickname=demo（不保存密码）；startAbility 成功后才 terminateSelf()；失败则停留并提示。
  • 启动 Main 后结束自身，建议配置 removeMissionAfterTerminate，避免返回键回到欢迎页。
  • 欢迎页定时器在 aboutToDisappear 中清理。
  • EntryAbility 不再声明 audioPlayback 后台模式。

MainAbility

  • 新文件，承接原 EntryAbility 的窗口、主题、AudioSession、ImageCache 初始化，并加载 Index。
  • launchType: singleton；处理 onNewWant（来自通知点击等情况）。
  • exported 设为 true 以便通知/卡片显式拉起，但 onCreate 先检查登录态：未登录就启动 EntryAbility 登录页并结束自己，防止绕过登录。
  • onDestroy 停止播放、停止后台任务、释放 AVSession/AVPlayer。

通知栏

  • AudioSessionService.createWantAgent() 目前写死 EntryAbility，改为 MainAbility；否则登录后点通知会回到登录页。
  • module.json5 把 backgroundModes: ["audioPlayback"] 从 EntryAbility 移到 MainAbility。
  • KEEP_BACKGROUND_RUNNING、INTERNET 的 usedScene.abilities 增加/改为 MainAbility。

退出登录

  • 停止播放、停止后台任务、释放音频会话；
  • 清除 isLoggedIn/nickname；
  • 显式启动 EntryAbility 的登录入口（带 showLogin=true 参数，跳过欢迎页）；
  • 结束 MainAbility。

4.2 四个 Tab、状态刷新、历史

  • 在 Index.ets 增加第 4 个 TabContent，把原“我的”里的收藏/历史拆成 FavoritesView。
  • ProfileView 改成个人中心；SettingsPage 从“我的”进入。
  • Tab 切换、onPageShow（从播放页返回）时重新读取收藏/历史并刷新统计。
  • 收藏 Tab 显示收藏/最近播放两个 segment；不新增数据库。
  • 播放历史统一在 PlayerService 内记录：在歌曲成功起播时写一次 StorageService.addPlayHistory，覆盖首页、歌单、搜索、播放页、上一首/下一首；避免 Index/SongListPage/PlayPage 各写一遍且漏写。
  • 播放器服务需要拿到 StorageService 的 context；在 MainAbility 初始化时注入/设置。
  • SearchPage.ets 没有任何路由引用，移出 main_pages.json 并删除；搜索只保留 Index 内的 SearchTab。
  • 移除顶部搜索/主题/背景菜单；背景功能收进 Settings（默认关闭，时间紧可隐藏入口）。

4.3 固定 demo 登录

  • AuthService：
    • validate(username, password)：空账号、空密码、账号/密码错误分别返回明确错误；只有 demo + 123456 通过。
    • login：成功后只保存 isLoggedIn=true 与 nickname=demo，不保存密码。
    • logout：清除登录态。
  • 登录页显示演示账号，协议勾选；错误文案在对应输入框下方。
  • 本地单元测试覆盖：空账号、空密码、错误账号、错误密码、正确账号。
  • 这是课程演示登录，不连接真实认证，不传输密码；报告里写明。

4.4 动态服务卡片

目标： 2×2 卡片显示“继续听”或“发现好音乐”，并在播放/刷新后更新；点击进入 App，未登录先登录。

实现

  • 新增 MusicFormAbility（FormExtensionAbility）和 MusicWidgetCard.ets。
  • form_config.json：2×2、ArkTS UI、updateEnabled: true，按 SDK 模板设置 updateDuration/scheduledUpdateTime，目标 30 分钟；具体字段以 SDK 模板和模拟器实测为准。
  • 数据源：本地 Preferences 的最近播放，不依赖网络。
    • 有历史：标题=最近歌曲名，副标题=歌手，状态=“继续听”；
    • 无历史：标题=“今天想听什么？”，副标题=“打开清听”，状态=“发现好音乐”。
  • 封面：使用本地渐变色/本地图标，不加载远程封面，保证离线可用。
  • 刷新链路：
    1. onAddForm 读取数据并保存 formId；
    2. onUpdateForm 读取最新最近播放；
    3. 系统定时刷新（按配置，约 30 分钟）；
    4. App 内播放歌曲变化/回到前台时，WidgetService.refreshAll() 读取 formId 并调用 formProvider.updateForm，实现立即更新；
    5. onRemoveForm 清理 formId。
  • 点击：postCardAction 以 router 方式拉起 EntryAbility；Entry 检查登录态，未登录进登录页，已登录直接进 Main。
  • 验收：
    • 桌面添加卡片，显示正确初始状态；
    • 播放本地示例或在线歌曲，回到桌面，卡片显示最近歌曲；
    • 等待定时刷新，卡片仍能更新；
    • 点击卡片能进入 App / 登录页。

4.5 本地示例音频（断网保底）

  • 新增 entry/src/main/resources/rawfile/demo_loop.wav，约 20–30 秒，项目自行生成的无版权环境循环；不依赖第三方音乐。
  • Song 增加可选字段 assetName?: string；新增一条 MockData.LOCAL_DEMO_SONG：
    • id: -1、名称“清听 · 示例曲”、歌手“清听”、专辑“本地示例”、assetName: 'demo_loop.wav'、url: ''。
  • PlayerService.playSong 增加本地分支：
    • 若 song.assetName 存在：通过 resourceManager.getRawFd(assetName) 获取 fd，设置 avPlayer.fdSrc = { fd, offset, length }；
    • 不请求 API、不请求歌词；歌词页显示“示例音频，无歌词”；
    • 切歌/停止时关闭旧 fd，避免资源泄漏；
    • 本地歌曲也写入播放历史，使卡片和“最近播放”有内容。
  • 本地示例出现在：
    • 首页“本地精选”/离线兜底列表；
    • 搜索兜底数据；
    • 设置页的“播放本地示例”入口（方便答辩演示）。
  • UI 标识“本地示例”，避免误认为是第三方版权音乐。
  • README/报告记录：该音频由项目生成，无第三方版权；不使用旧 讲解视频.mp4 或第三方音频。

4.6 深色播放页

固定深色，不跟全局主题；主界面保持浅色。

  • 新增页面级 token（放 AppStorage，仅播放页生效）：
    • playerBg #0B0C10
    • playerSurface #1A1A20
    • playerText #F5F5F7
    • playerMuted #C9C7D0
    • playerAccent #FF6B72
  • PlayPage.aboutToAppear 设置这些 token；aboutToDisappear 恢复浅色值。不要让全局 ThemeManager 变暗。
  • 背景：当前封面放大 + 模糊 + 深色遮罩（#0B0C10 65–80%）；无封面时用深色渐变。
  • PlayerControls、LyricView、音质弹层、播放列表弹层改为读取 player* token（或通过 props 传入深色 palette）；歌词在深色下使用 #C9C7D0，当前行 #FF6B72。
  • HdsNavigation 标题/菜单：使用深色模式或自定义顶栏；状态栏内容切白，退出播放页恢复；系统导航栏也切深色。
  • 主按钮使用 #FF6B72；白字在主色按钮上用更深的 #C8424C（浅色页面）或深色页专用色，保证对比。
  • 验收：浅色主界面进入播放页后，标题、歌词、时间、控制、弹层、状态栏都清晰可读；返回首页恢复浅色。

4.7 网络、缓存与错误处理

  • ApiService 增加连接/读取超时（建议 8–10 秒），不要无限等待。
  • 错误分类：无结果 / 网络失败 / 服务返回异常；UI 分别显示重试、空态、提示。
  • loadMore 只有请求成功后才增加页码；失败保留已有结果。
  • 播放地址为空或 AVPlayer error：由 PlayerService 暴露错误事件/返回状态，页面 toast + 可换歌/重试，不静默停住。
  • 保留 CacheService TTL；网络失败时展示 MockData 本地精选（其中本地示例可播放，其余仅展示信息）。
  • 首页加载失败不能一直 loading；设置超时和兜底数据。
  • 图片加载失败用本地渐变色占位。

7. 答辩讲解主线

  1. 产品定位：基于 wyyhm6 的在线音乐播放器，保留播放核心，补齐完整页面与产品闭环。
  2. 我的改动：
    • 4 Tab，新增收藏，重做个人中心；
    • 欢迎页 + 固定 demo 登录 + Preferences 登录记忆；
    • EntryAbility + MainAbility 双 Ability；
    • 动态 2×2 服务卡片，显示最近播放；
    • 播放页固定深色，局部主题不污染主界面；
    • 断网本地示例 + API 失败兜底。
  3. 数据流：搜索/推荐 → ApiService → 列表 → 点击 → PlayerService → AVPlayer；本地示例走 rawfile fdSrc。
  4. 取舍：不做后台数据库，保留网络 API + 多 Ability 两项加分。
  5. 演示顺序：欢迎 → 登录 → 首页 → 搜索 → 播放 → 收藏 → 我的 → 退出 → 桌面卡片 → 断网播放本地示例。

常见追问：

  • 为什么两个 Ability？登录与主界面职责分离，登录结束自身，主界面负责播放；符合 Stage 模型/Want。
  • 登录是真的吗？固定演示账号，本地校验，不发送密码。
  • 卡片怎么动态？保存 formId，App 播歌后更新；系统定时刷新用最近播放兜底。
  • 断网怎么播放？本地示例音频走 rawfile fdSrc，不依赖 API。
  • 为什么不做后台数据库？时间/部署/演示风险；API + 多 Ability 更稳。
  • 哪些是你做的？4 Tab、登录、双 Ability、收藏/我的、动态卡片、深色页、本地示例、兜底和文档。

8. 风险与应对

风险 应对
